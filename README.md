# 철거 견적 엔진 V2 — 실제 현장 데이터 연동판

목표: 사용자가 현장 동영상을 올리면 영상에서 철거항목·물량·현장조건을 구조화하고, 사용자 실제 단가/생산성 기준과 과거 실제 현장 데이터를 함께 사용해 예상 철거비 범위를 계산하는 모바일 우선 웹 프로토타입.

## V2 핵심 변경
- 과거 블로그 현장 40건 중 지출현황과 매칭 가능한 실현장 20건을 `data/historical_matches.json`에 연결
- 매칭 신뢰도(high/medium)와 `calibration_eligible`을 분리
- 원상복구가 섞인 계약 총액을 철거 단가로 역산하지 않음
- 과거 실적은 현재 단계에서 **유사현장 검색·검증·신뢰도 보조**에 사용하고 금액을 억지로 맞추지 않음
- 바닥/천장 범위가 불명확하면 전체 평수를 자동 적용하지 않음
- 숨은 바닥층(데코타일/몰탈/콘크리트/단차), 다실·가벽량, 사다리차 반출, 공용부 보양, 시간제한, 장비반입 가능 여부를 별도 변수화
- 일반 `반출 어려움 = 15% 할증` 같은 임의 퍼센트 보정을 제거하고 장비·운반·보양을 개별 산정하도록 변경
- 야간/민원도 고정 할증률을 임의 적용하지 않음
- 자기타일 철거+샌딩 단가는 아직 사용자 실제 단가 미확정이므로 자동가격에서 제외

## 실행
```bash
python -m venv .venv
# Windows
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
python app.py
```
브라우저: `http://127.0.0.1:5000`

## 가격 구조
`영상 → 철거범위/물량 → 인일 → 폐기물 → 장비 → 물류/시간조건 → 실제 단가 계산 → 과거 유사현장 검증 → 예상 범위`

AI는 가격을 결정하지 않습니다. `analyzer.py`는 현장을 읽고, `estimator.py`가 계산합니다.

## 실제 현장 데이터 사용 원칙
`historical_matches.json`에는 블로그 현장과 2022~2026 손익자료 매칭이 저장되어 있습니다. 매출/지출/인건비가 있어도 원상복구·신규공사가 섞인 현장은 가격보정에 사용하지 않습니다. 철거 단독으로 보이는 자료도 면적/물량 표준화가 부족하면 유사사례 검증용으로만 사용합니다.

## 다음 정확도 보강 우선순위
1. 자기타일 철거+샌딩 실제 단가
2. HWP 원본의 지출 상세항목(폐기물/장비/인건비/자재)을 현장별로 분해
3. 블로그 매칭 20건의 실제 면적·작업일수·폐기물차 대수 추가
4. 목재/집기 체적→차량수 환산
5. 석고천장, ALC, 조적, 유리, 닥트, 주방바닥 생산성 확정
6. 실제 영상 테스트에서 예측범위와 최종원가 오차율 기록


### 재무 데이터 검증 원칙
현재 과거 현장 매칭 재무값은 모두 검증 전 후보입니다. 특히 음수 손익 행은 실제 적자로 간주하지 않으며 가격 계산에서 제외합니다. 원본 현장명·계약/매출·정산범위가 1:1로 확인된 경우에만 calibration을 허용합니다.
